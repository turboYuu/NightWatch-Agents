# 依赖管理

项目采用**声明与锁定分离**：人只改声明文件，锁文件由工具生成。两个文件各司其职，都需要提交进 git。

| 文件 | 作用 | 谁来改 |
| --- | --- | --- |
| `pyproject.toml` | **声明**。唯一的依赖来源，只写宽松范围（如 `langgraph>=0.2`），不写死精确版本 | 人，手工编辑 |
| `conda-lock.yml` | **锁定**。记录每个包的确定版本、sha256 校验和、各平台构建 | 机器，由 `conda-lock lock` 生成，**不要手改** |

依赖分两组，定义在 `pyproject.toml`：

| 组 | 内容 | 何时安装 |
| --- | --- | --- |
| （默认）`[project].dependencies` | 运行时依赖：`langgraph`、`langchain-core`、`deepagents`、`e2b` | 总是 |
| `dev` | `pytest` / `ruff` / `mypy`（在 `[project.optional-dependencies]`） | 开发时 |

> `e2b` 之所以在**运行时**：它是 `SandboxBackend` 的唯一实现，没有可替代的后端。
> 早先它放在可选组 `sandbox`，是为了支持一个本地「假沙箱」后端；该后端因无隔离、
> 误用风险大已被移除，`e2b` 随之升为必需依赖。
>
> `deepagents` 之所以在**运行时**而不是可选组：`nw_agent.backends.SandboxBackend`
> 继承它的 `BaseSandbox`。deepagents 判定后端能力用的是类属性身份比对
> （`type(self).ls_info is not BackendProtocol.ls_info`），鸭子类型通不过，所以
> 必须真继承。代价是它会连带引入完整 `langchain` 及 `langchain-anthropic` /
> `langchain-google-genai`——这是本项目依赖里最重的一环，见「已知事项」。

## 安装依赖

### 前置：准备 conda-lock 工具

`conda-lock` 装在**独立环境**里，不要往 `base` 装——它依赖的 `packaging` / `requests` / `ruamel.yaml` 版本与 conda 自身冲突，solver 会直接拒绝。

```bash
conda create -n conda-lock -c conda-forge -y conda-lock
```

### 首次搭建 / clone 之后

在**仓库根目录**执行：

```bash
# 1. 按锁文件创建 nightwatch_agents 环境（含 dev 与全部运行时依赖）
conda run -n conda-lock conda-lock install -n nightwatch_agents conda-lock.yml

# 2. 把本仓库以可编辑模式装进该环境
conda run -n nightwatch_agents python -m pip install -e . --no-deps
```

第 2 步不能省，**而且每次重跑第 1 步之后都要补一次**：本地包（`nightwatch-agents`
自身）不参与依赖锁定，`conda-lock install` 对齐环境时会把它清掉——症状是
`ModuleNotFoundError: No module named 'nw_agent'`。第 1 步的目标环境已存在时
可以直接重跑，会按锁文件对齐版本。

沙箱后端 `e2b` 已随默认安装装入，无需额外可选组；真正跑沙箱任务时另需环境变量 `E2B_API_KEY`。

### 验证

```bash
conda run -n nightwatch_agents pytest     # 预期全绿；未设 E2B_API_KEY 时 E2B 用例跳过
```

## 新增依赖

**只改 `pyproject.toml` 一处**，然后刷新锁文件并重装：

```bash
# 1. 编辑 pyproject.toml，在对应分组里加一行。例如加运行时依赖：
#       dependencies = [..., "httpx>=0.28"]
#    加开发工具：
#       dev = [..., "types-requests>=2.32"]

# 2. 重新求解，刷新锁文件
conda run -n conda-lock conda-lock lock -f pyproject.toml

# 3. 按新锁文件重装环境
conda run -n conda-lock conda-lock install -n nightwatch_agents conda-lock.yml
```

第 2 步会重新解析全部依赖，过程中可能顺带升级其它包——这是预期行为。提交前扫一眼 `conda-lock.yml` 的 diff，它就是这次依赖变更的完整记录。

### 记录：为什么不用 `langchain-e2b`

早期计划是复用 `langchain-e2b`（E2B 官方的 LangChain 沙箱适配层）实现 E2B 后端，
P0 落地时**放弃了**，理由：

- 它**不带 `py.typed`**，在 mypy `strict` 下无法使用；
- 它是 `0.0.x`，没有 API 稳定性承诺；
- 它实际只提供「命令执行 + 文件读写」两件事，而裸 `e2b` SDK 自带类型标记，
  且 `commands.run` 原生支持 `cwd` / `envs`，比它的 `execute(command)` 更合用。

代价是自己在 `src/nw_agent/backends/e2b_backend.py` 里写异常归一化（几十行），
换来全程可静态检查。`deepagents` 也不需要 `langchain-e2b`——它需要的只是
「一个满足 `SandboxBackendProtocol` 的后端」，而那个后端就是我们自己。

## 已知事项

- **`deepagents` 是依赖里最重的一环。** 它会连带引入完整 `langchain` 及
  `langchain-anthropic` / `langchain-google-genai` / `langsmith` / `wcmatch`。
  这是「继承官方 `BaseSandbox`」的直接代价（原因见上文的分组说明），
  不是可以随手去掉的可选项。
- **锁定的版本可能高于声明的下界。** 例如 `pyproject.toml` 写 `langgraph>=0.2`，
  实际锁定到 `1.2.12`。写代码时要按锁定版本的实际 API，而不是声明的下界。
- **`langsmith` 被用到但不单独声明。** 可观测性只按约定设置环境变量
  （见 `src/nw_agent/observability/tracing.py`），**生产代码不 import 它**，故不必写进
  `pyproject.toml`；只有 `tests/test_tracing_live.py` 为了清掉 `get_env_var` 的
  `lru_cache` 才 import 它。等哪天生产代码真要直接调它的 API，再按上面的流程加声明并
  重跑 `conda-lock`。
- **Python 版本为 3.14**，由 `conda-lock.yml` 固定。
