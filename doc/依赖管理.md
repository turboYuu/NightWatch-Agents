# 依赖管理

项目采用**声明与锁定分离**：人只改声明文件，锁文件由工具生成。两个文件各司其职，都需要提交进 git。

| 文件 | 作用 | 谁来改 |
| --- | --- | --- |
| `pyproject.toml` | **声明**。唯一的依赖来源，只写宽松范围（如 `langgraph>=0.2`），不写死精确版本 | 人，手工编辑 |
| `conda-lock.yml` | **锁定**。记录每个包的确定版本、sha256 校验和、各平台构建 | 机器，由 `conda-lock lock` 生成，**不要手改** |

依赖分三组，定义在 `pyproject.toml` 的 `[project.optional-dependencies]`：

| 组 | 内容 | 何时安装 |
| --- | --- | --- |
| （默认）`[project].dependencies` | 运行时依赖：`langgraph`、`langchain-core` | 总是 |
| `dev` | `pytest` / `ruff` / `mypy` | 开发时 |
| `sandbox` | `e2b` 云端沙箱后端 | 需要跑沙箱任务时 |

## 安装依赖

### 前置：准备 conda-lock 工具

`conda-lock` 装在**独立环境**里，不要往 `base` 装——它依赖的 `packaging` / `requests` / `ruamel.yaml` 版本与 conda 自身冲突，solver 会直接拒绝。

```bash
conda create -n conda-lock -c conda-forge -y conda-lock
```

### 首次搭建 / clone 之后

在**仓库根目录**执行：

```bash
# 1. 按锁文件创建 nightwatch_agents 环境（默认含 dev，不含 sandbox）
conda run -n conda-lock conda-lock install -n nightwatch_agents conda-lock.yml

# 2. 把本仓库以可编辑模式装进该环境
conda run -n nightwatch_agents python -m pip install -e . --no-deps
```

第 2 步不能省：本地包（`nightwatch-agents` 自身）不参与依赖锁定，需要单独安装。第 1 步的目标环境已存在时可以直接重跑，会按锁文件对齐版本。

需要沙箱能力时，第 1 步追加 `-E sandbox`。

### 验证

```bash
conda run -n nightwatch_agents pytest     # 预期 5 passed
```

## 新增依赖

**只改 `pyproject.toml` 一处**，然后刷新锁文件并重装：

```bash
# 1. 编辑 pyproject.toml，在对应分组里加一行。例如加运行时依赖：
#       dependencies = [..., "httpx>=0.28"]
#    加开发工具：
#       dev = [..., "types-requests>=2.32"]
#    加沙箱依赖：
#       sandbox = [..., "e2b>=1.0"]

# 2. 重新求解，刷新锁文件
conda run -n conda-lock conda-lock lock -f pyproject.toml

# 3. 按新锁文件重装环境
conda run -n conda-lock conda-lock install -n nightwatch_agents conda-lock.yml
```

第 2 步会重新解析全部依赖，过程中可能顺带升级其它包——这是预期行为。提交前扫一眼 `conda-lock.yml` 的 diff，它就是这次依赖变更的完整记录。

### 示例：添加 `langchain-e2b`

`langchain-e2b` 是 E2B 官方维护的沙箱后端（导入名 `langchain_e2b`），属于沙箱能力，归入 `sandbox` 组。

**1. 改 `pyproject.toml` 的 `sandbox` 组**

```toml
sandbox = ["e2b>=1.0", "langchain-e2b>=0.0.6"]   # 云端沙箱后端（可选）
```

只加这一行。它自带的两条依赖会随锁文件一起解析，无需重复声明：

| 传递依赖 | 上游约束 | 本项目现状 |
| --- | --- | --- |
| `deepagents` | `>=0.6.0,<0.7.0` | 尚未声明，由本次引入 |
| `e2b` | `>=2.32.0,<3.0.0` | 已在 `sandbox` 组，锁定 2.52.0，满足 |

已核对上 PyPI 的 `requires_python` 为 `>=3.11,<4.0`，与项目固定用的 3.14 兼容。

**2. 刷新锁文件并安装**

```bash
conda run -n conda-lock conda-lock lock -f pyproject.toml
conda run -n conda-lock conda-lock install -n nightwatch_agents -E sandbox conda-lock.yml
```

`-E sandbox` 不能漏：默认安装不含 `sandbox` 组，漏了会出现「装完了却仍然 import 不到」。

**3. 验证**

```bash
conda run -n nightwatch_agents python -c "from langchain_e2b import E2BSandbox; print('ok')"
```

> 若代码里要直接 `import deepagents`（例如调用 `create_deep_agent`），建议同时在 `pyproject.toml` 的运行时依赖里显式声明它，别依赖 `langchain-e2b` 的传递依赖——上游收紧范围时会被动失去这个包。

## 已知事项

- **锁定的版本可能高于声明的下界。** 例如 `pyproject.toml` 写 `langgraph>=0.2`，实际锁定到 `1.2.12`。写代码时要按锁定版本的实际 API，而不是声明的下界。
- **`sandbox` 组尚未启用。** `e2b` 的包名与版本待 P0 验证后再收紧约束。
- **Python 版本为 3.14**，由 `conda-lock.yml` 固定。
