## 1. Python 标准库

### 1.1 argparse —— CLI 参数契约

**用在哪**：`src/nw_agent/cli/main.py`（`nw-agent` 入口）、`scripts/build_sandbox_template.py`、
`scripts/bench_sandbox_cold_start.py`、`scripts/run_eval.py`、`scripts/report_ledger.py`。

| 用法 | 作用 |
|---|---|
| `ArgumentParser(prog=..., description=...)` | 帮助页的「外壳」：用法行开头的命令名 + 下方总述 |
| `add_argument("--repo", required=True)` | `required=True` 让该项在用法行里**不带方括号**，一眼可辨必填 |
| `choices=[...]` | 自动在用法行生成 `{a,b,c}` 并做取值校验 |
| `action="store_true"` / `action="append"` | 布尔开关；可累积成列表 |
| `type=int` / `type=Path` | 顺带做类型转换 |
| `nargs="?"` + `choices` | 位置参数可有可无（`build_sandbox_template.py` 的 `action`） |
| `default=` | 缺省值，**不受 `choices` 约束** |
| `metavar` | 一般不必写：argparse 从选项名推导（`--budget-tokens` → `BUDGET_TOKENS`） |
| `parse_args(argv)` | 传 `list[str]`，测试可直接喂参数、不依赖 `sys.argv` |
| `parser.error(msg)` | 打印用法 + 错误到 stderr 后 `sys.exit(2)` |
| `parser.print_help()` + `return 2` | 实现「什么都不传就打印帮助」而不默认做事 |

**坑**

- **帮助页没有一行是「打印代码」**：整页由 `add_argument` 的声明拼出。改帮助 = 改声明，
  不是改输出逻辑（`cli/main.py` 的模块 docstring 列了完整对应关系）。
- **`--help` 与参数非法都抛 `SystemExit`**：前者退出码 0（正常退出），后者 2。
  因此测试用 `pytest.raises(SystemExit)` 断言即可，不必捕获输出流。
- **互斥与「二选一」要手写**：`--issue` 与 `--task` 的互斥是 `parser.error()` 手写的
  （`add_mutually_exclusive_group` 只能管互斥，管不了「至少给一个」）。
- **`choices` 不校验 `default`**：写了个非法默认值也能进来。
- 中文 `help` 文案容易超 `line-length=100` 触发 ruff E501——本仓库为此专门改过一次
  （`e080fa3 style: 修复 CLI help 文案超长`）。

### 1.2 dataclasses —— 不可变数据结构

**用在哪**：`SandboxConfig`、`VerifySpec`、`Case`、`CaseReport`、`RunRecord`、
`StageRecord`、`TracingStatus`——几乎全部数据模型。

- `@dataclass(frozen=True)`：不可变、可安全进 checkpoint、可当 dict 键、防「谁改了这个对象」。
- `field(default_factory=dict)`：可变默认值必须用 `default_factory`，不能直接写 `{}`。
- `replace(obj, field=value)`：派生新对象。`run_case` 用它注入 `eval_case` 标签，
  `observability` 的离线链路用它把沙箱路径改写到临时目录。
- **列表字段用 `tuple`**：frozen 只挡赋值，`obj.list_field.append()` 照样能改——等于冻结失败。
- **手写 `as_dict()`，不用 `dataclasses.asdict`**：后者递归展开且返回 `dict[str, Any]`，
  在 mypy strict 下比手写更松，也与 `CaseReport.as_dict` 的既有范式不一致。

**坑**：`replace()` 会重跑 `__post_init__`（`SandboxConfig` 的凭据校验因此每次派生都执行——
正确行为，但要意识到）；frozen 的 `__post_init__` 里想赋值得 `object.__setattr__`，
且**不要在那里做副作用**（写文件），否则会出现「构造失败但文件已写」的半状态。

### 1.3 pathlib / posixpath —— 路径

**用在哪**：`observability/store.py`、`evals/cases.py`、全部脚本与测试。

| 用法 | 说明 |
|---|---|
| `Path.home()` | 用户目录；`~/.nightwatch` 的基准 |
| `path.parents[1]` | 上两级（验收测试的 `conftest.py` 用它相对自身定位仓库根） |
| `path.rglob("*")` | 递归枚举；`relative_to(root).as_posix()` 转 POSIX 相对路径 |
| `read_bytes()` / `write_text(..., encoding="utf-8")` | 读写；**文本一律显式 utf-8** |
| `is_file()` / `is_dir()` / `exists()` | 判定 |
| `mkdir(parents=True, exist_ok=True)` | 建目录（幂等） |
| `PurePosixPath` | 纯路径运算，不碰文件系统；沙箱是 Linux，统一走 POSIX |
| `posixpath.join` / `posixpath.relpath` | 拼/算沙箱内路径——**不要用 `os.path`**（Windows 会出反斜杠） |

**坑**

- **`resolve()` 在 macOS 会把 `/var` 变成 `/private/var`**，让「我传的路径」与「回读的路径」
  字符串不等。故 `nw_home()` 刻意**不做 realpath 归一**。
- 解析路径是纯计算，**目录创建要推迟到真写文件的那一刻**：否则 import 一个模块就会在用户
  磁盘上留目录（见 `store.ensure_parent` 的分工）。

### 1.4 json —— JSON 与 JSONL

**用在哪**：`observability/ledger.py`（账本）、`evals/cases.py`（用例清单）、
`scripts/run_eval.py`（报告落盘）、运行快照。

- `json.dumps(obj, ensure_ascii=False, indent=2)`：中文保持可读，不转 `\uXXXX`。
- **JSONL**（一行一个 JSON 对象）：逐行独立、可追加、可 `grep`/`jq`。账本用这个形态，
  代价是查询要自己写（故配了 `scripts/report_ledger.py`）。
- `json.loads` 返回 `Any`：本项目一律**在入口函数里绑成 `object` 再逐字段校验**，
  把 `Any` 关在一个函数内（`cases.load_case`、`ledger._record_from`）。

**坑**

- **`json.JSONDecodeError` 是 `ValueError` 的子类**：所以 `except (ValueError, KeyError,
  TypeError)` 能一并兜住坏行。
- **`True` 是 `int` 的子类**：`isinstance(v, int | float)` 会把 JSON 的 `true` 当数字，
  于是「单价手抖写成 `true`」变成单价 `1.0`。价格表里因此显式排除 bool。
- **别用 `cast(Case, data)` 了事**：那等于把校验责任丢掉，出错点会被推到很深的地方。
  逐字段校验才能做到「非法数据构造不出来」（与 `SandboxConfig.__post_init__` 同一哲学）。

### 1.5 typing —— 类型标注（配合 mypy strict）

**用在哪**：`src/` 全量。

| 用法 | 说明 |
|---|---|
| `Literal["ok", "error"]` | 封闭取值集合；运行时仍需自己校验（mypy 管不到 JSON） |
| `Protocol` | 结构化子类型：`Recorder` 不要求实现类继承它 |
| `cast(T, x)` | 收窄类型；也是**挡住 mypy `warn_return_any`** 的手段 |
| `TYPE_CHECKING` | 只在类型检查期导入：`evals/runner.py` 因此运行时**不依赖** observability |
| `X \| None`、`isinstance(x, int \| float)` | 可空与 3.10+ 的联合类型判定 |
| `Callable[[SandboxConfig], SandboxBackend]` | 后端工厂的签名——接缝的核心 |

**坑**

- **`dict` 取值是 `Any`，会顺返回类型扩散到全项目**：`cases.py` 的 `_require_*` 助手一律
  「入参 `object`、返回具体类型」并在内部 `cast`——这是被 mypy strict 逼出来的范式。
- **`Protocol` 的签名要逐字兼容**：实现多一个**带默认值**的关键字参数是允许的
  （`RunContext.finish(..., escaped=None)` 就是这样满足只声明 `outcome/error` 的 `Recorder`），
  返回类型必须协变兼容。
- `str` 赋给 `Literal[...]` 字段必须先 `cast`，mypy 不会因为你「刚校验过」而放行。

### 1.6 collections.abc —— 抽象容器类型

**用在哪**：函数签名（`Mapping` / `Sequence` / `Iterable` / `Callable` / `Iterator`）与
`isinstance` 收窄。

签名用抽象类型而非 `list`/`dict`，调用方传 tuple、generator、自定义映射都行。
需要保证顺序时（报告可比）才在内部 `sorted` 后返回 `list`。

### 1.7 re —— 正则

**用在哪**：`evals/checks.py`（解析补丁头）、`scripts/report_ledger.py`（解析 `--since`）、
`tests/test_evals.py`（源码边界断言）。

- `re.compile` 预编译 + **命名组** `(?P<name>...)`：`checks.py` 的 `_HEADER` 一次抓出四个
  候选路径（含引号与裸 token 两种形态）。
- **非捕获组 `(?:...)`**：避免生成多余分组。
- `re.MULTILINE`：`^` 变成「行首」——源码边界断言（「`evals/` 里不得 import e2b」）靠它。
- `pattern.match(string, pos)`：带起始位置的匹配（解析 git 的八进制转义 `\344`）。

**坑**：匹配**字面反斜杠**要写 `\\\\`（字符串里两个 → 正则里一个）；
`re.match` 只锚定开头、`re.search` 才是任意位置，别混用。

### 1.8 fnmatch / shlex —— 匹配与 shell 转义

**用在哪**：`backends/upload.py`（凭据文件名黑名单）、拼命令的 `interface.py` / `e2b_backend.py`。

- `fnmatch.fnmatch(text, pattern)`：通配符匹配，**`*` 会跨 `/`**——正因如此 `.ssh/*` 能匹配
  `.ssh/keys/id_rsa` 这类嵌套路径。**大小写不敏感要靠显式 `.lower()`**（POSIX 上 fnmatch 区分大小写）。
- `shlex.quote(value)`：把变量拼进 shell 命令前必须引用。所有拼命令的地方
  （`mkdir -p`、`git config`、`test -e`）都过了它——**这是防注入的硬要求，不是风格问题**。

### 1.9 datetime / time / uuid —— 时间与 ID

**用在哪**：`observability/run_context.py`、`evals/runner.py`、各脚本。

| 用法 | 说明 |
|---|---|
| `time.perf_counter()` | **单调时钟**测耗时；不用 `time.time()`（会被系统时钟调整影响） |
| `datetime.now(UTC)` | 3.11+ 的 `datetime.UTC`；`run_id` 的时间戳部分用它 |
| `datetime.now().astimezone()` | 附本地时区，用于人读的 `started_at` / `finished_at` |
| `isoformat(timespec="seconds")` | 秒级精度，账本可读 |
| `datetime.fromisoformat(...)` / `timedelta` | 回读；`--since 7d / 12h` 靠它 |
| `uuid.uuid4().hex[:8]` | `run_id` 的随机后缀，防同秒撞车 |

**坑**

- **naive 与 aware 的 datetime 不能比较**（`TypeError`）。`--since` 传纯日期时没有时区，
  代码里显式 `.astimezone()` 补本地时区再比。
- `timespec="seconds"` 会截断亚秒：极快的用例 `duration_seconds` 会是 `0.0`——这是精度取舍，
  不是 bug（改细会让账本变吵）。

### 1.10 os.environ —— 环境变量

**用在哪**：`observability/store.py`（`NW_HOME`）、`observability/tracing.py`（LangSmith 开关）、
测试的 `monkeypatch.setenv`。

`os.environ.get(name)` 拿不到返回 `None`；写入是**进程全局**副作用，故测试一律用
`monkeypatch.setenv` / `delenv`（用例结束自动恢复）。

**坑**：**空串 ≠ 未设置**。`NW_HOME=""` 若按「已设置」处理，根目录会变成当前目录（很意外）。
故一律用 `os.environ.get(...) or default` 的 `or` 语义，而不是 `is not None`。

### 1.11 logging —— 库的日志

**用在哪**：`backends/interface.py`、`backends/e2b_backend.py`（全仓库仅此两处）。

`logger = logging.getLogger(__name__)`（模块级唯一），
`logger.warning("…%s", value, exc_info=True)`——`%s` 惰性格式化 + 带堆栈。

**坑**：**库不自配 handler**（不调 `basicConfig`）。本项目全程没有 handler 配置，输出形态
交给使用方；这也是脚本层全部用 `print`（面向人的表格输出）的原因。

### 1.12 其余标准库速览

| 模块 | 用在哪 | 要点 |
|---|---|---|
| `abc.abstractmethod` | `backends/interface.py` | 声明 `upload_tree` / `execute_detached` / `kill` 为抽象方法 |
| `subprocess` | `tests/e2b_double.py` | `run(shell=True, cwd=, capture_output=True, timeout=, env=)`；超时抛 `TimeoutExpired` |
| `shutil.which` / `shutil.copytree` | 测试 | 能力探测（宿主有没有 git）→ `skipif`；复制真实用例再改坏它 |

| `statistics.median` | `scripts/bench_sandbox_cold_start.py` | 多次重复取中位数，比均值抗异常值 |
| `sys` | 全部脚本/入口 | `sys.path.insert(0, src)` 让未安装也能跑；`sys.exit(main())` 透传退出码 |

## 2. 沙箱与协议：e2b + deepagents

### 2.1 e2b SDK（生产链路）

**用在哪**：`src/nw_agent/backends/e2b_backend.py`、`scripts/bench_sandbox_cold_start.py`。

| API | 说明 |
|---|---|
| `e2b.Sandbox.create(template=, timeout=, metadata=, envs=, api_key=)` | 建远端沙箱；`metadata` 用于对账与费用归因 |
| `sandbox.commands.run(cmd, cwd=, envs=, timeout=)` | 执行命令，**原生支持 cwd 与环境变量** |
| `sandbox.files.write_files([{path, data}])` | 单请求批量写（上传主路径） |
| `sandbox.files.write(path, content)` | 逐文件写（批量失败时的降级路径，为了拿到 per-file 错误） |
| `sandbox.files.read(path, format="bytes")` | bytes 模式返回 `bytearray`，要 `bytes()` 转一下 |
| `sandbox.sandbox_id` / `sandbox.kill()` | 标识与销毁；`on_timeout` 默认 `"kill"` |
| `e2b.CommandExitException` | **非零退出走异常路径**，输出挂在 `exc.stdout/stderr/exit_code` |
| `e2b.TimeoutException` / `e2b.SandboxException` | 超时与基类异常 |

**坑**

- **cwd 指向不存在的目录会被拒**：所以「建仓库目录」这一步**不能用 `execute`**（cwd 就是那个
  还不存在的目录），必须走不设 cwd 的 `execute_detached`。这是接口里那个看起来多余的抽象
  方法的全部理由。
- **非零退出不返回「带退出码的结果」而是抛异常**：写后端时必须 `try/except` 把异常归一成
  `ExecuteResponse`，而不是判 `result.returncode`。
- 刻意**不用 `langchain-e2b`**：它是 0.0.x、不带 `py.typed`（mypy strict 下不可用），
  而它只提供「执行 + 读写」两件事，裸 e2b 的 `cwd` / `envs` 反而更合用。

### 2.2 deepagents 的 `BaseSandbox` 与协议

**用在哪**：`src/nw_agent/backends/interface.py`。

- `SandboxBackend` **继承** `deepagents.backends.sandbox.BaseSandbox`，而不是自带 `Protocol`。
- 原因：deepagents 判定后端能力用的是**类属性身份比对**，形如
  `type(self).ls_info is not BackendProtocol.ls_info`。鸭子类型（结构子类型）**通不过**，
  会被误判成「实现了旧 API」并走进废弃分支。
- 代价：`deepagents` 必须进**运行时**依赖，并连带引入完整 langchain 及
  `langchain-anthropic` / `langchain-google-genai` / `langsmith`（见[依赖管理](依赖管理.md)）。
- **推论：子类绝不能覆写 `ls_info` / `grep_raw` / `glob_info`**——覆写这三个名字等于对
  deepagents 宣称「我实现的是旧接口」。
- 只实现 `upload_tree` 即可：`upload_files` 由接口层委托过去，避免同一件事写两遍。
- `ExecuteResponse(output, exit_code, truncated)`：`truncated` 是「输出被截断」的信号，
  截断责任在本层（`cap_output` 按**字节**截断，并用 `errors="ignore"` 丢弃多字节字符的残片）。
- `create_deep_agent(model=, system_prompt=, backend=)`：P1 的装配入口。

### 2.3 e2b Template API —— 模板即代码

**用在哪**：`scripts/build_sandbox_template.py`。

| API | 说明 |
|---|---|
| `Template().from_base_image()` | 从官方 `e2bdev/base` 起步（已带 envd 等运行前提） |
| `template.apt_install([...])` | 装系统包 |
| `template.pip_install("pytest")` | 默认 `g=True`，内部以 **root** 执行 |
| `template.run_cmd([...], user="root")` | 传**列表**即多条命令合并成一条 RUN；可指定执行用户 |
| `template.set_workdir(path)` | 设工作目录 |
| `Template.to_dockerfile(t)` | **离线渲染成 Dockerfile**——不联网、不需 Key，故能把模板内容钉成可跑 CI 的回归 |
| `Template.build(t, name=, skip_cache=, on_build_logs=)` | 服务端构建；返回 `info.name/template_id/build_id` |

**坑**

- **不要调 `set_start_cmd`**：模板的就绪命令为 `None` 时会继承基底的 envd 启动逻辑，
  重写反而把它顶掉。
- **`to_dockerfile()` 会丢掉 RUN 的执行用户**：想断言「这一步必须以 root 跑」得读
  `template._template._instructions`（私有属性，仅供测试，见 `tests/test_sandbox_template.py`）。

### 2.4 `create_deep_agent` 装配（P1 第一周实测）

**用在哪**：`src/nw_agent/agents/factory.py`（装配）、`runner.py`（跑一次）、
`tests/agent_stub.py`（离线 stub 模型）。

| API | 说明 |
|---|---|
| `create_deep_agent(model, tools, *, system_prompt, subagents, backend, name, ...)` | 除 `model`/`tools` 外全 keyword-only；返回 `CompiledStateGraph` |
| `model=` | 收 `str \| BaseChatModel`；字符串走 `init_chat_model`，`provider:model` 形式 |
| `subagents=[{name, description, system_prompt}, ...]` | 暴露成名为 **`task`** 的工具（入参 `description` + `subagent_type`） |
| `backend=` | 注入 7 个工具：`ls` / `read_file` / `write_file` / `edit_file` / `glob` / `grep` / `execute`，全部作用在沙箱内 |
| `system_prompt=str` | 是**追加**（我们那段在前，deepagents 自带的 base prompt 在后），不是替换 |

**坑（全部实测踩过）**

1. **`write_file` 只能新建文件，已存在即失败**（`BaseSandbox.write` 的 docstring 原文：
   「Create a new file, failing if it already exists」）。改已有文件**必须用 `edit_file`**
   （`old_string` / `new_string`）。提示词里必须写清，否则模型会一直撞这个错。
2. **deepagents 会自动补一个 `general-purpose` 子代理**，它继承主代理全部工具——于是
   `task` 工具暴露的子代理类型比你在 `subagents=` 里声明的更多。可用
   `register_harness_profile(..., GeneralPurposeSubagentProfile(enabled=False))` 关掉（beta API），
   或提供一个同名 spec 顶掉它。**默认行为要有测试钉住**，否则升级后会悄悄变宽。
3. **缺 key 时 `init_chat_model('anthropic:...')` 构造不报错**，报错推迟到首次调用。
   后果：① 离线测试不能用字符串 model（要传预建实例），否则错误会晚到「已经建了沙箱、
   已经花了钱」才出现；② `--dry-run` 挡得住配置串写错、**挡不住假 key**，要如实说明。
4. **token 用量必须走 callback，不能从 `invoke` 的返回值里数**：子代理在独立上下文里跑，
   顶层 `messages` 会把子代理的消息折叠掉（实测 2 条 vs callback 的 4 次 `on_llm_end`）。
   字段用 `AIMessage.usage_metadata`，**不是** `response_metadata`（后者字段名不统一，常为空）。
5. **回调里抛异常默认被吞**：`handle_event` 捕获 handler 的异常后只打 warning，除非
   handler 的 `raise_error = True`（`langchain_core/callbacks/manager.py` 里
   `if handler.raise_error: raise`）。**预算熔断要生效，这个类属性必须设**。
6. **`recursion_limit` 默认 9999**（deepagents 写死进自己的 config）：不给上限的循环能烧一整晚。
   在 `invoke(config={"recursion_limit": ...})` 里覆盖。
7. **写测试 stub 时的两个硬要求**：`_llm_type` 必须是 **property**（抽象方法，且中间件会读它）；
   `bind_tools` 基类直接 `raise NotImplementedError`，必须覆盖。另外 stub 决策要**按
   `bind_tools` 收到的工具名 + messages 里已有的 ToolMessage**来判断下一步，**不要按调用轮数**
   ——嵌套循环的轮次取决于实现细节。
8. **`langgraph` / `langchain_core` / `deepagents` 都带 `py.typed`**，strict 下会真的解析那些
   长泛型：`create_deep_agent` 的返回类型里 ContextT 无法在调用点闭合，需要**一处** `cast`
   （别让它扩散），`invoke` 的 `dict[str, Any] | Any` 要在一个收窄函数里处理完。
9. **用非 anthropic / google 的 provider 要显式声明 provider 包**（如 `langchain-deepseek`）：
   `init_chat_model("deepseek:...")` 按 provider 前缀查注册表，包不在就报「不认识的 provider」，
   而且**报错时机是运行期**——建完沙箱、花掉钱之后。它还会连带引入 `langchain-openai` /
   `tiktoken`（DeepSeek 走 OpenAI 兼容接口）。
10. **provider 上报的模型名可能与配置串不同**：实测配置写 `deepseek:deepseek-v4-flash`，
   账本里记的是 `deepseek-flash`（provider 自己的标识）。填 `prices.json` 时要按**账本里的名字**
   填，别按配置串——所以 `report_ledger.py` 会把缺单价的模型名列出来。

## 3. 可观测性：langsmith / langchain-core

**用在哪**：`src/nw_agent/observability/tracing.py`（只设环境变量）、
`tests/test_tracing_live.py`（真链路自测）。

**以下事实在已安装的 `langsmith 0.14.4` 源码里核对过，出处同时写在 `tracing.py` 里**：

| 事实 | 出处 | 影响 |
|---|---|---|
| 开关判定是 `get_env_var("TRACING_V2", default=get_env_var("TRACING"))` 再 `== "true"` | `utils.py:141-142` | **只认小写字符串 `true`**；`True` / `1` / `yes` 都无效 |
| `get_env_var` 带 `@functools.lru_cache(maxsize=100)`，全库无 `cache_clear` | `utils.py:420` | **晚设的环境变量会被缓存屏蔽** |
| 变量前缀 `LANGSMITH` 优先、`LANGCHAIN` 兜底 | `utils.py:425` | 新名优先，旧名仍生效 |
| `tracing_is_enabled()` 不在 import 期求值 | `run_helpers.py` | 只要在**第一次被 trace 的调用之前**设好变量就有效 |
| `Client` 读 key / endpoint 走**未缓存**路径 | `client.py:711,1283` | 鉴权侧不受 lru_cache 影响 |
| 缺 key 只 warn、不抛，`post()` 失败被吞 | `run_helpers.py:1917` | **trace 会静默丢失**——这是「缺 key 必须显式报告」的技术依据 |

**用法要点**

- **生产代码不 import langsmith，只设环境变量**：LangChain 家族按约定识别变量，因此
  `pyproject.toml` 与锁文件都不用动（它已作为 deepagents 的连带依赖存在）。
- **顺序契约**：`load_dotenv` → `configure_tracing()` → 再触发任何被 trace 的调用。
  CLI 的 `main()` 第一行就调它，正是为了抢在 lru_cache 之前。
- **key 与开关必须同时具备**：只设 key 不会上报（gate 要求 tracing 判定为真）。
- **`traceable` 包一个平凡函数即可产生真实 run**，不需要任何 LLM 调用——所以「接线自测」
  在 P0 就能跑通（`tests/test_tracing_live.py`）。
- `Client().list_runs(project_name=...)`：`post()` 是**后台线程异步上传**，断言前要**轮询**。
- 测试里反复切换开关需 `langsmith.utils.get_env_var.cache_clear()`。

**坑**

- 值写成 `"1"` 是最常见的无效配置——不报错，只是不上报。
- 用户 shell 里可能已有自己的 tracing 消费者：**只在 `--trace` 时设置变量，缺席时一个都不碰**，
  更不能写 `false`（那会意外关掉别人的采集）。

## 4. 测试：pytest 与测试替身

### 4.1 pytest 用法

**用在哪**：`tests/` 全量。

| 能力 | 用在哪 / 说明 |
|---|---|
| `tmp_path` | 所有需要落盘的测试；本仓库**没有任何测试往用户目录写文件**（`Path.home()` 只被读一次，用来断言默认路径） |
| `monkeypatch.setenv/delenv/setattr` | 环境变量与属性的临时替换，用例结束**自动恢复** |
| `conftest.py` + `@pytest.fixture(autouse=True)` | 把 `NW_HOME` 钉到 `tmp_path`——**机制而非纪律**，任何测试都写不到真实用户目录 |
| `pytest.mark.parametrize` | 一套逻辑跑多组输入（用例 ID、坏清单、凭据路径） |
| `pytest.raises(Exc, match="…")` | 断言异常类型**与**消息（`match` 匹配 `str(exc)`） |
| `pytest.mark.skipif(cond, reason=)` | 真链路门控（无 Key 时 skip 而非 fail） |
| `pytest.importorskip("mod", reason=)` | 依赖缺失时整文件跳过；**放模块顶层**、在被测模块导入之前 |
| `capsys` | 捕获 stdout（`--print-dockerfile` 的离线验收路径） |

**坑**

- **`skipif` 的条件在 import 期求值**：读的是**测试进程启动时**的环境。`.env` 不会被 pytest
  自动加载，故「key 只写在 `.env` 里」会让真链路测试静默跳过。正确姿势是在环境里带上 key：
  `conda run -n nightwatch_agents pytest tests/test_backends_e2b.py -o addopts="" -s`。
- **`-o addopts=""`**：覆盖 `pyproject.toml` 的 `addopts="-q"`，因为真链路测试要 `-s` 看实时输出。
- **`pythonpath=["src"]`** 让测试无需先 `pip install -e .`；副作用是**pytest 通过不能证明安装
  可用**——验证安装要用 `nw-agent --help`。
- **prepend 导入模式**会把测试文件所在目录插进 `sys.path`，所以 `tests/` 里的同级模块可以裸
  import（`from e2b_double import SandboxDouble`）。`scripts/` 不在这个机制里——`scripts/` 下
  的脚本要**显式**把该目录插进 `sys.path` 才能被测试 import（见 `tests/test_sandbox_template.py`
  顶部的 `sys.path.insert`）。

### 4.2 测试替身（SDK double）与「假后端」的区别

**用在哪**：`tests/e2b_double.py`、`tests/eval_harness.py`。

- `SandboxDouble` 是 **e2b SDK 的双胞胎**，不是「第二个后端实现」：通过
  `E2BSandboxBackend._attach(config, double)` 注入，走**生产后端的同一条代码路径**，
  只是把远端换成宿主机临时目录。
- **它只存在于 `tests/`**：产品代码 import 不到，`create_backend()` 也造不出它。这是它与
  「本地假沙箱」的本质区别——后者一条 `rm -rf ~` 就能毁掉开发机（产品说明 3.3 已删掉它）。
- 替身刻意**翻译不了的**是沙箱绝对路径。这个约束反过来塑造了生产代码：用例数据里不许出现
  沙箱根路径、`ACCEPTANCE_PATH` 做成 config 字段、命令一律用相对路径。
- `ScriptedSolver`（`tests/eval_harness.py`）：按清单尝试越权写入的攻击脚本。放测试而不放
  产品包里——产品包里不该出现攻击代码。

## 5. 环境与工程配置

### 5.1 conda-lock 与 conda（声明与锁定分离）

**用在哪**：`pyproject.toml` 的 `[tool.conda-lock]` 与 `[tool.conda-lock.dependencies]`、
`conda-lock.yml`、[依赖管理.md](依赖管理.md)。

- **`pyproject.toml` 是唯一的声明来源**，`conda-lock.yml` 由它生成，不手工改锁文件。
- 只有 `[tool.conda-lock.dependencies]` 里列出的（python、pip）走 conda，其余按 pip 处理
  （`default-non-conda-source = "pip"`）。
- `conda-lock` 装在**独立环境**里：它依赖的 packaging / requests / ruamel.yaml 与 conda 自身
  冲突，装不进 base。
- 常用命令（也写在 `pyproject.toml` 注释里）：
  `conda run -n conda-lock conda-lock lock -f pyproject.toml`；
  `conda run -n conda-lock conda-lock install -n nightwatch_agents conda-lock.yml`；
  `pip install -e . --no-deps`（本地包单独装，不参与锁定）；日常执行一律 `conda run -n ...`。

**坑**：**锁定的版本可能高于声明的下界**（声明 `langgraph>=0.2`，实际锁到 `1.2.12`）——
写代码按**锁定版本**的实际 API。而 `ruff` / `mypy` 的 `target-version` 按**最低支持版本**
（py311），保证「声明的最低版本确实能跑」。

### 5.2 hatchling（构建后端）

`[build-system]` 选它是因为配置少；src 布局下**必须显式声明 `packages = ["src/nw_agent"]`**，
否则找不到包。`[project.scripts]` 的 `nw-agent = "nw_agent.cli.main:main"` 生成同名命令。

### 5.3 ruff（lint + import 排序）

```toml
select = ["E", "F", "I", "UP", "B"]   # pycodestyle / pyflakes / isort / pyupgrade / bugbear
line-length = 100
target-version = "py311"
```

**坑**

- **未启用 `W`（空白符）与 `D`（docstring）**：所以「文件末尾缺换行」这类不会被拦下。
- **`line-length = 100` 对中文按字符计**：长中文注释极易超行，既有做法是**拆成多行 `#`
  注释块**、断在短句处（见 `interface.py`、`cli/main.py`）。
- `UP` 会纠正过时写法（`datetime.timezone.utc` → `datetime.UTC`，被自动改过一次）。
- `--fix` 可自动修 import 排序（`I001`）与部分 UP 规则；跑完看一眼 diff。

### 5.4 mypy（strict）

```toml
python_version = "3.11"
strict = true
files = ["src"]        # 只查源码，测试与脚本不查
```

- **`files = ["src"]`**：测试与 `scripts/` 不在检查范围内——所以脚本里可以出现
  `dict[str, Any]`、`assert isinstance(...)` 这类宽松写法（一种刻意的「缓冲带」）。
- **strict 下 `warn_return_any`**：从 `dict` 里取值返回会报错，必须 `cast`。
- 第三方库需要带 `py.typed` 才能在 strict 下使用——这是不用 `langchain-e2b` 的直接原因。

## 6. Docker 与镜像构建（E2B 模板即 Dockerfile）

**用在哪**：`scripts/build_sandbox_template.py`；背景与实测数据见[沙箱基准](沙箱基准.md)。

| 概念 | 在本项目里的形态 |
|---|---|
| 基础镜像 | `FROM e2bdev/base`——已带 envd 等运行前提，裸 ubuntu 要复刻这些才能被 SDK 驱动 |
| `DEFAULT USER` 继承 | 基底声明 `DEFAULT USER user`(uid 1000)，构建期 `run_cmd` 也以它执行 |
| 层缓存 | 命中缓存的步骤**其内容不进新快照** |
| `WORKDIR` | 会以 root 建出目录 → 沙箱用户写不进去，故要显式 `chown` 给 `user` |
| 构建即服务端构建 | `Template.build(...)` 在 E2B 侧跑，几分钟、会计费 |

**坑（都是实测踩过的）**

1. **`/tmp` 不在构建层缓存的快照里**：把「下载安装器」与「执行安装器」拆成两条 RUN 时，
   一旦下载那步命中缓存，后一条会 `bash: /tmp/xxx.sh: No such file or directory`（exit 127）。
   **解法：下载与安装放同一条 RUN**；代价是 RUN 边界不再标示断点，故用 `echo '[n/4] …'`
   编号标记补回来（失败时看最后一条标记就知道断在哪）。
2. **非 root 写不进系统路径**：`/opt`、`/`、`/usr/local/bin` 都归 root。装 conda 到
   `/opt/conda`、写软链到 `/usr/local/bin` 都必须 `user="root"`。
3. **`chown -R /opt/conda` 会让百余 MB 在新层里复制一份**，正好抵消换 Miniforge 省下的体积。
   正确做法是**只把 conda 需要写的两个空目录**（`envs`、`pkgs`）交给沙箱用户。
4. **软链要克制**：只链 `conda` 本体，**不链 python/pip**——链了会顶掉系统 python，而 pytest
   装在系统 python 上，两者混用会让「到底哪个解释器在跑」不可预测。
5. **`bzip2` 不是可选项**：conda 安装器解包依赖它，缺了会在安装中途失败。
6. **`DEFAULT USER` 与提权兜底**：镜像给 `user` 免密 sudo，于是上游后端能用
   `sudo -n install -d -o "$(id -u)"` 兜底建目录。用 `install -d` 而非 `chown -R` 的理由：
   后者作用在父目录上，若路径配成 `/repo` 这类根下路径，`chown -R /` 会改掉整个文件系统的属主。
7. **下载成功 ≠ 是可执行脚本**：错误页或被截断的响应同样是 HTTP 200，直接丢给 `bash` 只会
   得到含糊的语法错误。故先 `head -c 2 | grep -q '#!'` 校验 shebang，并给 curl 加 `--retry 3`。
8. **Miniforge vs Miniconda**：默认 Miniforge（走 conda-forge、无附加条款、包小约 37%、
   自带 mamba）；两者都是 constructor 装出来的，`bash installer -b -p <prefix>` 用法一致，
   可随时用 `--miniconda` 换回。

## 7. Git 工程实践

**用在哪**：`backends/interface.py`（沙箱内建基线、导 diff）、`evals/cases.py` 与用例目录
（golden 补丁）、仓库管理（`.gitignore`）。

| 用法 | 说明 |
|---|---|
| `git add -N .` | 让**未跟踪**的新文件以 `new file mode` 出现在 diff 里；对已被 `.gitignore` 忽略的文件无效 |
| `git --no-pager diff HEAD` | **必须比 HEAD**：裸 `git diff` 只比「工作树 vs 索引」，agent 若执行过 `git add`，改动已进索引，裸 diff 会**静默返回空** |
| `git init` + `config user.email/user.name` | 沙箱镜像里通常没有全局 git 配置，不显式给会让 commit 以 exit 128 失败 |
| `git config commit.gpgsign false` + `commit --no-gpg-sign` | 模板可能继承了 `gpgsign` 配置却没有 GPG key |
| `git commit --allow-empty` | 文件集为空时也要有基线，否则 `diff HEAD` 无从比较 |
| `git apply -p1` | 默认剥掉 `a/` `b/` 前缀；**`diff -u` 手搓的补丁前缀是裸路径，会剥错** |
| `git diff HEAD > reference.patch` | 生成 golden 补丁的标准做法（前缀 `a/` `b/`）；`git apply` 不校验 `index` 行，只看文本 |
| `git rev-list --count HEAD` | 断言「恰好一个基线提交」 |
| `git check-ignore -v <path>` / `git add --dry-run` | 验证忽略规则——`.gitignore` 是**静默**的，只能靠这两条证伪 |
| `git log origin/x..HEAD` | 看本地领先远端哪些提交（无 `gh` 时的审查入口） |

**坑**

- **`.gitignore` 会静默吞掉刻意放进来的文件**：注入用例的 decoy `.env` 就被根规则 `.env`
  忽略过——用例看着存在、实则没有诱饵。解法是加**否定规则** `!evals/cases/*/repo/.env`，
  并用 `git add --dry-run` 复核。
- **否定规则的前提**：文件本身被忽略可以再包含，但**父目录被排除时无法再包含**其下文件。
- **`git add -N` 与 `.gitignore` 的组合会假绿**：被忽略的新文件不进 diff，于是「改了」被判成
  「没改」。故评测用例的 `repo/` 里**禁止出现 `.gitignore`**，用例加载期直接报错。
- 提交信息里**不加任何 AI / 工具署名**（本仓库的硬要求）。

## 8. 设计与安全概念

### 8.1 分级验证：正确性证据 vs 强制护栏

- **L1**（仓库测试通过）/ **L2**（编译、类型、lint 通过）是**正确性证据**，至少满足其一。
- **L3**（未修改 `target_files` 之外的文件）是**强制护栏**，与 L1/L2 是 **AND** 关系：
  `test_passed = (L1 或 L2) 且 L3`。
- **L3 只证明「没乱改」，不证明「改对了」**——空改动也能通过 L3。PR 描述里要如实标注命中的
  验证层级，别把「只有护栏通过」包装成「测试通过」。

### 8.2 隐藏验收与「改前必红、改后必绿」

- 正确性判据**不能只看仓库自带测试**：空改动同样能通过它（`bugfix-off-by-one` 用例刻意造出
  「仓库测试在带 bug 的快照上也绿」）。
- 做法：用例目录里放 `acceptance/`，**solver 跑完、补丁抓完才上传**——既不污染 diff
  （`git add -N` 会把它算成新增文件），也让 solver 改不到判据。
- **`null` solver 必红 / `reference` solver 必绿**这两条参数化断言，是用例有效性的机器化证明。
- 断言要能堵住假解：行为不变（防「删函数体只留 docstring」）、反向哨兵（防「改错对象」）、
  内容与长度下限（防「凑数」）。

### 8.3 检测 vs 拦截（逃逸计量）

- P0 只**检测**越权写入（diff 路径比对白名单 + 凭据形态路径），写白名单**拦截**留 P1。
  理由：先能观测，才谈拦截。
- `escape_count` 是 5.7 的硬红线（恒为 0）。
- `null` / `reference` solver 下的 `escape = 0` 是**平凡结论**（它们不攻击）；真正证明
  「检测器有效」的是 `ScriptedSolver` 发起的越权写入必须被计成逃逸。

### 8.4 接缝设计：Protocol / 工厂 / 注入

| 接缝 | 形态 | 换掉它意味着 |
|---|---|---|
| 沙箱后端 | `create_backend(kind, config)` 模块级工厂 + `SandboxBackend` 抽象类 | 换隔离方案只改一处 |
| 求解器 | `Solver` Protocol（`solve(case, backend)`） | P1 接入 DeepAgent 时用例数据不动 |
| 观测 | `Recorder` Protocol，默认 `NoOpRecorder` | 关掉观测不改变行为 |
| 后端工厂 | `Callable[[SandboxConfig], SandboxBackend]` | 离线（替身）与真链路共用同一条流程 |

- **默认值必须是 no-op 对象本身**（而非「恰好指向临时目录的真实现」）：前者是类型级保证，
  后者只是环境巧合。
- **观察者不该有返回值**：否则调用方会开始依赖它，「关掉观测会改变行为」就不远了。

### 8.5 数据口径三条铁律

1. **缺数据是 `None`，不是 `0`**：`tokens`、`cost_usd` 缺数据一律 `None`——写 0 会被读成
   「零成本」。
2. **部分求和是谎言**：只要有一个模型缺单价，总费用就整体记 `None`，并列出缺哪些模型。
3. **三态结果**：`success` / `fail` / `error`。`error` 是 harness 故障（后端建不起来、
   golden 补丁打不上），**不计入成功率分母**，但单独计数并让脚本非 0 退出——否则无法区分
   「期望的 0%」与「意外的 0%」。

### 8.6 幂等、原子与清理

- **`kill()` 必须幂等**：「节点正常结束 kill 一次 + finally 再兜一次」是常态，第二次调用不得
  抛异常。`ledger.append` 拒绝重复 `run_id` 同理（防同一次运行写两遍把指标刷高）。
- **`__exit__` 返回 `False`**：不吞异常——清理失败不得掩盖原始业务异常。
- 需要「读-改-写」的地方（如账本判重）在并发下**不是原子的**：本项目靠 `run_id` 唯一性
  （uuid）保证正确，属「已知但无害」。
- **终止必清理**：任何走到 END 的路径（含失败/中止）都要销毁沙箱，异常路径用 `finally` 兜底。

### 8.7 安全：凭据隔离与外发声明

- **凭据只存宿主机**：GitHub Token 绝不进沙箱，所以沙箱被 prompt injection 攻破也偷不到能改写
  仓库的凭据；宿主与沙箱之间**只交换 diff 与测试输出**。
- 两道运行期强制（不是注释）：
  - `SandboxConfig.__post_init__` 拒绝含 `TOKEN/SECRET/KEY/PASSWORD/CREDENTIAL` 的 **env 键**
    → 非法配置**构造不出来**；
  - `upload.select_upload_files` 的文件名黑名单（`.env`、`.ssh/*`、`*.pem`…）→ 凭据类文件
    **不上传**，被拒路径留痕（静默丢弃会让人查不出任务为何缺文件）。
- **代码外发必须显式声明**：E2B 沙箱（目标仓库代码上传到第三方执行）与 LangSmith（Issue 正文、
  代码片段、diff、提示词上传到 SaaS）是**同一性质**的风险，私有仓库/含密钥仓库默认不建议用。
- **shell 注入**：拼命令的变量一律 `shlex.quote`。
- **最小权限**：`write_file` 的白名单校验在服务端实现层（不放进工具签名让模型填）。

## 9. 坑速查表

| 坑 | 一句话结论 |
|---|---|
| 沙箱里 `git diff` 返回空 | 用 `git diff HEAD`（agent 可能已 `git add`） |
| 新文件不出现在 diff 里 | 先 `git add -N .`；但它对 `.gitignore` 忽略的文件无效 |
| 手搓补丁 `git apply` 报「does not apply」 | 用 `git diff` 生成（`a/` `b/` 前缀），别用 `diff -u` |
| 沙箱里 commit 失败（128） | 显式 `git config user.email` / `user.name` |
| `git apply` 报 GPG 相关错误 | `git config commit.gpgsign false` + `--no-gpg-sign` |
| 建目录的命令在沙箱里失败 | cwd 不能指向尚不存在的目录 → 用不设 cwd 的执行路径 |
| 非 root 建不出 `/workspace` | 镜像给免密 sudo，用 `sudo -n install -d -o "$(id -u)"` 兜底 |
| 模板构建报 `/tmp/x.sh: No such file` | 下载与安装必须同一条 RUN（`/tmp` 不在层缓存快照里） |
| conda 装了却用不了 | `envs` / `pkgs` 目录要 `chown` 给沙箱用户 |
| 模板改动没生效 | 层缓存；必要时 `--skip-cache` |
| `--help` 之后代码没执行 | 它抛 `SystemExit(0)`，属正常退出 |
| 想改帮助页却找不到打印代码 | 整页由 `add_argument` 拼装；改声明 |
| `choices` 的 `default` 不生效 | `choices` 不校验默认值 |
| mypy 报 `Returning Any` | 从 `dict` 取值必须 `cast`，或用 `_require_*` 助手收窄 |
| 中文注释触发 E501 | `line-length=100` 按字符计；拆成多行注释 |
| 两个 datetime 比较报 TypeError | naive 与 aware 不能比，先 `.astimezone()` |
| 测耗时忽大忽小 | 用 `time.perf_counter()`（单调时钟） |
| `NW_HOME=""` 导致产物落到当前目录 | 空串按未设置处理（`or` 语义） |
| 测试往真实用户目录写文件 | `conftest.py` 的 autouse fixture 钉住 `NW_HOME` |
| LangSmith 的 env 改了没生效 | `get_env_var` 有 `lru_cache`；要早设，或测试里 `cache_clear()` |
| tracing 打开了但服务端没数据 | 值必须是精确小写 `"true"`；且 key 与开关必须同时具备 |
| 真链路测试莫名 skip | `skipif` 在 import 期读环境变量；`.env` 不会被 pytest 加载 |
| 跑真链路看不到实时输出 | 加 `-o addopts="" -s` 覆盖 `pyproject.toml` 的 `-q` |
| 价格表里写了 `true` | JSON 的 `true` 是 `int` 子类，会被当成单价 1.0；显式排除 bool |
| 指标莫名其妙掉了 | 先看账本有没有「未知 schema 版本」被跳过——口径变更会被读成回归 |
| 用例的诱饵文件不见了 | 根 `.gitignore` 静默吞掉；加否定规则并用 `git add --dry-run` 复核 |
| `repo/` 里放了 `.gitignore` | 会让 `git add -N` 漏掉新增文件 → 假绿；用例加载期直接拒绝 |
| 模型反复「写文件失败」 | `write_file` 只能新建，改已有文件要用 `edit_file` |
| `task` 工具里多出一个没声明过的子代理 | deepagents 自动补的 `general-purpose`；要关得用 harness profile 或同名 spec |
| 离线测试用字符串模型却晚到才报错 | 缺 key 时 `init_chat_model` 构造期不报错；测试要传预建模型实例 |
| token 统计比实际少一半 | 子代理的用量不在 `invoke` 返回值里，必须从 callback 的 `on_llm_end` 収 |
| 预算熔断不生效（异常没冒出来） | callback 里的异常默认被吞；`TokenSink.raise_error = True` |
| 一个卡住的循环烧到天亮 | deepagents 的 `recursion_limit` 默认 9999；在 `invoke(config=...)` 里覆盖 |
| 运行期报「不认识的 provider」 | provider 包要自己声明（`langchain-deepseek` 等）；deepagents 只带了 anthropic / google |
| `prices.json` 填了却不生效 | 键名要按**账本里的模型名**（provider 上报的），不是 `NW_MODEL_*` 的配置串 |
| 真链路测试莫名 skip | pytest 不加载 `.env`，而 `skipif` 在 import 期读进程环境；先 `set -a; source .env; set +a` |
